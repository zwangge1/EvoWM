## 诊断支持先调整训练

已有纯监督两层对照在八项读数中七项的误差点估计低于BM/OU，仅股骨落后。这说明现有两层结构具备较好的预测能力，宜先调训练配方，而不是立即更换层级或把BM预测拼接成所谓新模型。

| 原模型 | 总腿长 | 股骨 | 胫跗骨 | 跗跖骨 | 联合骨比 |
|---|---:|---:|---:|---:|---:|
| 完整两层full | .075473 | .065084 | .076143 | .110243 | .079817 |
| 纯监督两层supervised | .070651 | .061997 | .071481 | .107152 | .081208 |
| 单层single | .071181 | .061751 | .070502 | .108128 | .080038 |
| BM＝OU | .072450 | .055965 | .071807 | .116388 | .088163 |

这些是同一1,096种、168科的旧结果，不能当成本轮优化后的提升。supervised的比例略差于full，尚未观察到明确差异；其总长和绝对骨长较好，两个训练种子的方向一致。

原full完整生态条件只占训练12.5%，潜表示prediction目标的局部梯度较强，而4000步终点训练误差仍下降。因此候选依次检验：完整条件概率0.75、两层prediction权重0.25、不同总长/比例辅助权重，以及8000步重新训练。保留原SIGReg，不改两层架构和原始输入输出。所有候选必须参加内层比较，没有根据外层结果临时新增配方。

总长误差能解释full相对supervised的一部分短板；但股骨不能只看总长。full相比BM，股骨MSE多0.001104，分解为总长项+0.000447、比例项−0.000720、交叉项+0.001377。full的股骨比例误差其实较低，BM更强的负误差抵消也帮助了绝对股骨预测。总长偏差的平方仅占full总长MSE约0.4%，简单增加常数并不能解决问题。

完整诊断位于`outputs/allen_optimize_v4_diagnostic_temp/`。其中oracle表使用了目标真实答案来定位误差来源，不能作为新预测结果或可达性能下界。

## 服务器运行

在原evowm环境和tmux中操作。将GPU编号换成当时可用的卡，最多四张。

```bash
cd /mnt/zihanw/EvoWM
git pull --ff-only origin main
SOURCE_RUN="outputs/allen_overnight_v3_20261110_150810_454903"
GPUS="0 1 2 3" HOURS=8 EVAL_WORKERS=32 bash scripts/allen_world/run_optimize_v4.sh --source-run "$SOURCE_RUN" --smoke &&
GPUS="0 1 2 3" HOURS=8 EVAL_WORKERS=64 bash scripts/allen_world/run_optimize_v4.sh --source-run "$SOURCE_RUN" --full
```

smoke为10个64步任务，仅检查流程。full为170个训练任务，按选定配方需要约84万至96万训练步；前次350任务约80万步、耗时约3.5小时，可作为量级参考，新轮实际时间由GPU负载和评估速度决定。HOURS=8是停止继续派发训练的软时间窗口，不是八小时后强行中断；已启动训练、排队CPU评估和经典基线会继续收尾。

完整运行如果未结束，可恢复同一run：

```bash
GPUS="0 1 2 3" HOURS=8 EVAL_WORKERS=64 bash scripts/allen_world/run_optimize_v4.sh --resume outputs/allen_optimize_v4_实际时间
```

明确失败需检查logs并修复环境，随后加`--retry-failed`。未完整完成的训练会先归档，再从头跑原预算；已完整训练仅评估未完成则复用原checkpoint。代码改变需要新run。

无需先把本地BM结果传回服务器，脚本会自动CPU补齐；若服务器已经有对应完整BM run，可以加`--baseline-run outputs/allen_phylo_baselines_v1_...`复用。最终打印`DOWNLOAD=outputs/allen_optimize_v4_..._review.tar.gz`，审阅包自动排除.ckpt。下载这个包即可查看实际优化结果。
