# Allen 两层解剖尺度预测 v3：实现与运行

日期：2026-11-10。状态：实现完成，本地验证记录见文末；服务器实验尚未启动。本轮是开发比较，不预设两层优胜，也不将预测响应称为真实祖先演化轨迹。

## 实现内容

保留原 v2 单层代码、配置和历史结果。新增 `src/evowm/models/allen_anatomical.py`，上游训练入口仅增加显式开关与训练集读出配置，变动登记于 `hjepa/UPSTREAM.md`。两层仍复用原 JEPA 编码器、Transformer 预测器、残差初始化、表示匹配及 SIGReg 工具。

L1 是细粒度形态表示（128维），L2 是以总长读出约束的整体形态表示（16维）。编码为 L1→L2；预测由 L2 提供整体状态和预测总长，再调节 L1 的骨段分配与外测跗跖读出。两层对应同一个目标物种，不使用原生时间层级或按生态标签分组的 units。

参考输入为三个参考物种的四项形态及缺失掩码。条件保留 v2 的117维接口，包含温度、觅食环境、发育方式、体重、运动与其他背景及亲缘距离；两层都可访问这些条件。目标物种的形态只用于训练误差。训练和评估统一调用 `predict_from_context`，高层传给低层的始终是预测量。

三骨总长只由股骨、胫跗骨、跗跖骨全部实测的记录生成。比例使用两个独立坐标 `log10(股骨/跗跖骨)`、`log10(胫跗骨/跗跖骨)`，转成三个正比例，再由预测总长乘比例还原各骨长度。外测跗跖独立读出。缺骨不产生总长或比例真值，不用插补标签。

所有配置使用相同的有效骨长误差、总长误差、两个比例坐标误差，权重为1、0.25、0.25。这三类损失包含重复的形态信息，属于固定重加权，并非新增独立数据。当前权重是开发设置，尚未经过内部调参验证，不根据真实骨段温度排序调权重。

## 五种配置与四个问题

| 配置 | 区别 | 与完整模型比较的含义 |
|---|---|---|
| `allen_v3_full` | 两层、完整预测整体表示与总长进入细层、JEPA目标 | 候选完整模型 |
| `allen_v3_no_link` | 高层仍预测总长并参与三骨重构；取消高层对比例及外测跗跖的条件输入 | 整体信息是否帮助局部预测 |
| `allen_v3_scalar` | 只将预测总长传给细层，屏蔽丰富整体表示 | 高层表示是否超出一个总长数值 |
| `allen_v3_supervised` | 相同两层信息路径，去除表示匹配和SIGReg | JEPA联合训练目标是否优于相同结构的普通监督 |
| `allen_v3_single` | 单层、同样的总长和比例输出监督，预测器加宽 | 两层是否超出近似容量匹配的单层 |

完整模型、no_link、scalar、supervised均为1,714,052个参数。single将三个预测器前馈块宽度由512增至616，共1,713,916个参数。single适配器保留的零输入槽位对应8,256个不受数据梯度更新的权重；扣除后与完整模型的有效容量差约0.49%。因此称“近似容量匹配”，不称严格等效容量。no_link和scalar相应零输入槽位为1,088和1,024个权重。

这些控制均从头训练，使用相同分折、样本窗口、种子和步数，不给完整模型独享旧检查点预训练。四组比较分别支持不同主张；不能只凭完整模型优于Ridge就宣称层级或JEPA必要。OU尚未接入，历史过夜结果的线性基线是Ridge，不是OU。

## 本轮统一修正

1. **冻结分折。** 新配置显式读取CSV里的 `allen_frozen_family_fold` 及metadata里的映射，校验资格样本、seed、fold数和科归属；不再依赖不同pandas版本对同大小科的排序。旧配置默认分折行为不变。
2. **逐样本归一化。** 新模型统一将上游投影器的BatchNorm换为LayerNorm，避免训练窗口后续位置通过批统计影响前面的预测。此修改只作用于显式v3模型；全部v3对照一致。因此v2与v3的绝对差不能全部归因于层级。
3. **完整推理路径。** 验证、条件遮蔽、温度扰动均执行完整模型，不绕过上层，不对新模型另拟合事后probe。

## 实验矩阵与判读

短检查 `--smoke`：5种架构 ×（一个已知温度梯度模拟 + 真实表）× seed13 × fold0，每项64步，共10项。只检查训练、保存、加载、评估与汇总流程，不要求模拟校准通过。

完整开发 `--full`：5种架构 × 6模拟场景 × 2种子 × 5折 =300项模拟，加50项真实数据训练，共350项。模拟每项2000步、真实每项4000步。所有任务统一batch128。

六模拟为零温度效应、运动效应、已知正向梯度、温度×暴露调节并含运动效应、各骨等响应、反向梯度。这轮沿用v2生成器以直接检查旧失败是否改善；它还不等于穷尽“共享整体→局部分配”的生成机制。新非线性整体/分配模拟、OU基线、外部骨骼数据和换树属于后续方法推广验证，不能用本轮开发比较替代。

首要层间读数为完整三骨共同样本上的两坐标联合RMSE，同时报告总长、各骨及外测跗跖误差。先在物种内平均窗口误差，再按科等权。`comparisons_v3.csv` 中 `control_minus_full_rmse > 0` 表示完整模型误差较小；记录四组逐seed/fold配对，核对参考及目标窗口身份和样本数。这里不把seed/fold当独立生物重复做显著性检验。

温度诊断保留年均温、最热月、最冷月单独扰动及三温度共同平移。六模拟和不利结果全部保留。`calibration.json`沿用既有开发误差阈值；不是显著性检验，也不会自动授权稿件结论。短检查由于场景/种子/折不齐，校准标记false属预期。

## 服务器运行

在现有 `evowm` 环境和tmux中操作。先拉代码并查看空闲GPU：

```bash
cd /mnt/zihanw/EvoWM
git pull --ff-only origin main
nvidia-smi
```

以下0、1仅是GPU编号示例，替换为实际空闲卡；同时最多4张。先跑短检查，命令退出码0且 `completion.json` 的 `all_done` 为true才启动完整开发矩阵。

```bash
GPUS="0 1" EVAL_WORKERS=32 bash scripts/allen_world/run_overnight_v3.sh --smoke
```

短检查通过后，在空闲卡上运行：

```bash
GPUS="0 1 2 3" HOURS=8 EVAL_WORKERS=32 bash scripts/allen_world/run_overnight_v3.sh --full
```

CPU评估默认32并发，可改64；每张训练卡默认4个计算线程、8个加载进程。最多四张GPU。`HOURS=8`限制新训练任务的启动窗口；已启动任务及其评估会继续，因此总耗时可能超过8小时。不按旧单层耗时保证本轮一定一夜跑完。

每次打印独立 `RUN_DIRECTORY=outputs/allen_overnight_v3_...`。运行器复制输入表、列metadata、冻结分折与树，保存代码副本、SHA256、git状态、环境、日志及计划；不会在原表位置重新prepare。需要续跑时使用该实际目录，不修改源码或任务矩阵：

```bash
GPUS="0 1" HOURS=8 bash scripts/allen_world/run_overnight_v3.sh --resume outputs/allen_overnight_v3_实际时间戳
```

失败任务经检查后，续跑命令加 `--retry-failed`。首次失败会停止发起新任务，在途任务完成；退出码1表示失败、2表示还有待跑任务、3表示参数/快照核验失败。源码或输入快照改动后须另建运行，避免混合版本。

最终需查看 `completion.json`、`jobs.csv`、`summary.csv`、`comparisons_v3.csv/json`、`calibration.json`、`evaluation/` 与 `logs/`。下载整份新 `allen_overnight_v3_...` 文件夹即可；不要与旧 `allen_v1` 或 v2 结果混淆。
